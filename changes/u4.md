- Area `tdd`: `tdd lock` appends append-only C07 entries (POSIX paths, CRLF-normalized SHA-256, requirement ids read from `# REQ:` marker lines, the locked commit); a changed test is locked again only by a superseding entry that names an approved C33 change request for the same test path; `tdd change-request new` appends an `open` C33 row with the next free id and never writes `approved`.
- `tdd commit --red|--green|--refactor T-NNN -m TITLE PATH... [--approved ID] [--body TEXT] [--apply]` stages explicit files and writes a C32 message; it refuses a red with a non-test file or an unlocked test, a green or refactor that touches a locked test or the lock file, a green without an earlier red for the task, anything else already staged and a subject over 72 characters.
- `tdd check [--range R] [--replay]` proves from git history that every green follows a red of its task, that no commit touches a path locked at its parent, that the lock is append-only and every superseding entry names an approved request, that every locked file still matches its newest entry at the end of the range, that no commit adds a skip, expected-failure, only or todo marker and that a test file's assertion count never drops; the only exemption is a `Test-Change-Approved: <id>` trailer naming an approved request for that path whose spec changed in the same range. `--replay` checks each red commit out in a temporary worktree under the configured temp root and requires its new tests to fail there; the worktree is removed even when the test command fails or times out.
- Shared modules `batuta_lib/tdd_history.py` (every git call, the history rules and the replay), `batuta_lib/tdd_lock.py` (the lock and change-request files) and `batuta_lib/test_markers.py` (hashes, requirement ids, markers and assertion counts, with `ast` for Python).
