- Area `gate`: `gate evidence-lint` checks a gate evidence file (C09) with comments stripped first: no open critical or major finding on a PASS, a re-check line per fixed finding, a real reproduction on every open or fixed finding, unique finding ids, the gate and feature that match the file, and the routed role and model (critical gates the reviewer on the critical model, every other gate the adversary on the routine model, `gates.critical_units` routing the build gate of a critical unit); `gate status` shows or updates a feature's status file (C10) atomically (dry run by default, a passed gate needs valid evidence in order, a waiver is never set by a command); `gate check` enforces strict gate order, valid evidence for every passed gate, evidence commits that belong to the history and never go backwards (the release evidence describes the head), the L5-freeze approval with every hash recomputed (C06, with the typed phrase and a human approver), dated human waivers, a phase that follows the gates, and the release rules at L9 (readiness gaps listed, a readiness document once L6 passed).
- `gate thresholds`: the C11 ratchet. `--check` replays the history (chain, dates, same-date human waivers of L9-promote for every decrease, values equal to the history's end) and, with `--against REF`, the committed baseline (append-only history, nothing removed or lowered silently); `--propose name=value` records a raise in the history and refuses a decrease without a waiver and a reason.
- `gate promote`: the port of the merge gate. A pull request (`--repo`, `--pr`) is promoted only when every check concluded SUCCESS for the exact head (a pending check is never green, a skipped or neutral check is not evidence, a required check that never ran is refused), pinned to the checked head; a head without CI checks accepts local evidence recorded for that exact SHA, which never overrides a check that exists; a local branch (`--branch`, `--into`, `--local-evidence`) follows the same rule and never switches branches. The merge command is printed and run only with `--apply`.
- `gate hook-stop` and the handler `gate-stop` (`HOOKS`): the Stop hook blocks once when a unit with uncommitted changes has a failing gate check, appends a dated UNVERIFIED line to the unit's status file on the second attempt and allows the stop, and never blocks a session that changed no unit.
- Area `skeleton`: `skeleton check` verifies the readiness document (C27): current catalog hash, no more than `--lag` code commits behind the head, every catalog row labelled real or served by a provider with its provenance, `--release` lists every component that is not real as a gap; the contract tests of the catalog exist and their recorded status passes; the preview record (C29) is valid and, only with `--check-network`, reachable.
- Area `provider`: `provider lint` checks that every catalog row declares its availability states (C22) with a test per state that exists and is its own, that the provider state matches the provider column, and validates model cards (C28); `provider check` validates a runtime availability block (C26) and that its state is one the row declares.
- Area `lessons`: `lessons check` requires a C19 lesson line in `LESSONS.md` for every unit whose L7-build passed.
- Agents `adversary` (sonnet, high effort; read tools and Write for its one evidence file, Edit denied; the adversary procedure in its body) and `test-author` (sonnet, medium effort; failing tests first, never implementation code); templates `templates/gates/` (status, evidence, thresholds, readiness) that pass their own contracts.
- Shared modules `batuta_lib/gate_model.py`, `evidence.py`, `thresholds.py`, `readiness.py`, `promote.py`; git is reached only through `gate_model.Git`, so tests stand in for it.
- Fixes after the adversary check of U5: `gate check` runs the thresholds ratchet against the base revision of the checked range and routes by the base revision's `gates` settings (a change inside the range is a WARN naming the commit); evidence must not predate the newest change to a path its gate judges; the evidence model is compared by its whole name; `gate tests-record` writes the C34 contract-tests record and `skeleton check` and the release gate read it (a failed or skipped test fails, a record older than the code fails); `lessons check` ignores comments and code fences and blank fields; local promotion evidence must show tests that ran; the Stop handler keeps its own bounded once-per-failure state, reads unit write scopes from the sizing and says why when it fails open; the adversary agent records that its tool scope is enforced by the guards.
