- Area `init`: `init user` creates the user's `batuta.json` (C01) when missing, deploys the device copy, restores the settings presets and the user core (the device area) and installs the agent files into `~/.claude/agents/`; `init project` renders the project template into a folder (AGENTS.md, a short CLAUDE.md within the project core budget, `.claude/settings.json` merged append-only, `.batuta/batuta.json`, the constitution, thresholds, an example feature with its status file, a foundation test and the `batuta-gates` workflow). Both are dry runs unless `--apply`, back up with a stamp any file they replace, never overwrite a user file silently, and write an install manifest (`installed.json`: path, hash, backup, folders created; a project's manifest holds no machine path).
- `init doctor` runs the device check plus probes (Python 3.10, Git Bash on Windows for the plugin channel, Node and the `claude` CLI as warnings, the plugin's `python` option, configuration, roots writable) and, in a project, fails when the `tests` step of the `batuta-gates` workflow is not exactly `tdd.test_command`; `init update` renders again from the current templates and backs up what changes; `init uninstall` restores backups and removes only files whose hash is unchanged (an edited file is kept and reported DIFFERENT).
- Project template `plugins/batuta/templates/project/` (all templates now live inside the plugin, so a marketplace copy of `plugins/batuta/` alone runs `init` and `device deploy`) and `copier.yml` (four questions and a hidden release tag: `project_name`, `python_version`, `test_command`, `default_branch`, `batuta_ref`; placeholders only, so copier and `init project` render the same bytes). The workflow `batuta-gates` runs the configured test command, `tdd check --replay`, `spec trace`, `gate check`, `gate thresholds`, `guard scan`, `context check` and `leaks scan` against the base commit of the pull request (or the previous commit of the push); a WARN (exit 2) is reported and does not fail the job, a FAIL does.
- Areas `fragments` (`changelog` and `i18n` merge of per-unit fragments) and `reserve` (`next`, `list`: sequence numbers reserved under a lock in `<coordination root>/delegation/reservations.md`), generalized from the tools that run parallel units today.
- npx entry `bin/batuta.mjs`: Python discovery (`BATUTA_PYTHON`, then `py -3` on Windows, `python3`, `python`; the first that reports 3.10 or newer wins), arguments and exit code passed through, and an exact message naming what was tried when no Python is suitable.
- Shared module `batuta_lib/install_manifest.py` (the install manifest of `init`).
- Ownership in `init`: seed files (`.batuta/batuta.json`, the constitution, thresholds, the example feature, the foundation test) are yours after the first install and are never overwritten, not even with `--force`; managed files (AGENTS.md, the workflow, agent files) are updated only while they are an unchanged installed copy, a hand-edited one is kept (DIFFERENT, exit 2) unless `--force`, which backs it up first; an existing CLAUDE.md (project or user core) keeps its content and gains one marker-delimited managed block.
- Safety: `Manifest.load` refuses a base that leaves the project or the Batuta home (a committed manifest is untrusted input) and `init uninstall` refuses the whole manifest, deleting nothing, for a base, a path or a link that points elsewhere; the dispatcher's usage errors exit 1 (2 means WARN only) and the workflow's gates step fails when the Batuta script is missing; `render.write_atomic` and the new `write_atomic_bytes` retry `os.replace` a few times on a transient Windows access error.
- The example feature carries one valid requirement and task (C05 and C21 hold for every rendered file); `changes/u0r3.md` holds bullets only and `fragments changelog` skips `*-plugin-readme.md`.
- The doctor skill runs `init doctor --channel plugin` first and keeps its other checks.
- Manifest anchor: it holds folders only, and only folders on the project's own path or inside it; the settings merge and the device area write through the shared retrying writer.
