- Area `dispatch` (contract C30): `dispatch plan` validates a brief and a lane against the configuration and writes the request; `dispatch run` is a dry run by default and `--apply` executes the lane under a monotonic time limit and the per-task cost cap (`caps.max_cost_usd_per_task`); `dispatch resume` continues the saved Agent SDK session of an unfinished result within the cap that is left. Every run writes a C30 result and a ledger row (Model, Provider, Tokens in, Tokens out, Cost USD, Status) through `delegation.update_ledger`.
- Lanes: `subagent` returns the exact launch specification for the main session and never claims to have launched anything (the result is `pending`); `sdk` drives the Claude Agent SDK on an API key (the package is imported lazily and the lane refuses with the install command when it is missing), runs the batuta guards through the C31 launcher as the PreToolUse policy, adds a write-scope check for write tools, runs the brief's checks itself before marking the result complete and sends a failure back to the agent for at most two rounds; `provider:<name>` makes one tool-less call and returns a report and an optional patch that is written next to the report and applied only after the gates.
- Provider adapters over a pluggable standard-library HTTPS transport: `openai-compatible` (OpenAI, Azure OpenAI, vLLM, a LiteLLM gateway, Ollama), `gemini`, `bedrock` (Converse) and `vertex` (Claude `rawPredict`). Retries on 429, 5xx and connection errors are bounded (at most four, exponential backoff with jitter, `Retry-After` honoured up to 60 s, never past the deadline); `--transport-fixture FILE` replays answers from a file with no network.
- Cost caps and prices: `batuta_lib/dispatch/prices.json` lists USD per million tokens by provider and model with the source URL and the date read; an unverified or missing price refuses a paid lane unless `--allow-unpriced` is given. The output budget of a call is bounded by what the cap still buys, a projected cost over the cap stops the run before anything is sent, and an answer that costs more than the cap is discarded and recorded as `over-budget` with its partial cost.
- Credentials are read at call time from the environment variable named in `batuta.json` (or the `dispatch.sdk.key_file` of the sdk lane), never written to disk or printed: every output, result, report note and ledger cell passes through a redactor that masks the value, its JSON and URL encodings, common token shapes and credential headers. A provider patch outside the brief's write scope is refused, and a brief whose kind needs tools (implement, job, skeleton, run) is refused on a provider lane unless `--report-only` is given.
- Review fixes (the Opus code review of the first version): cost is cumulative per task across every call, crash, timeout and resume (the spent amount lives in `<id>.dispatch-state.json`, every call gets at most the cap that is left, and a call that ends without usage figures is charged its full allowed budget); everything the provider lane writes (report, patch, gate text, result, ledger cells) passes through the redactor; the PreToolUse policy runs every configured guard and the strictest answer wins (deny over ask over allow), off the event loop, honouring each registry entry's matcher and timeout; the default guard set is the guard area's handler ids (the sdk lane refuses to run with no guard); the sdk policy denies reading the process environment and pushing to shared branches, merging and deleting; the brief's checks run inside `--hours` and also gate a provider lane result (a patch leaves it `incomplete` until the checks can run on the patched tree); a billed call whose answer cannot be parsed records the usage it carries, else its allowed budget; resume counts the time earlier runs used; a request whose scope or report differs from its brief is refused; git-quoted patch paths are decoded before the scope check.
- `delegation.ledger_set_cells` (moved from the dispatch area, tested in `tests/test_delegation_cells.py`): the ledger keeps one writer and one set of text functions.
- Prices: the Vertex rows are unknown (null) until a Google page confirms them, Bedrock rows stay null and name the `global.` inference profile id, `gpt-5.4` and `gpt-5.5` carry their long-context tier above 272000 input tokens, the Azure `api-key` header is confirmed on Microsoft Learn.
- Re-check fixes: the provider lane charges every attempt that may have billed (an error after the request was sent, a 5xx or 408 answer) its full allowed budget and sizes the next attempt to what is left of the cap, stopping `over-budget` when that cannot cover an attempt (a 429 answer and an error before the send retry without a charge); the spend state is keyed by the task (`<delegation folder>/<brief id>.dispatch-state.json`), not by the request file's path; an invalid guard matcher denies the call; the sdk policy denies shell writes (redirects, tee, cp, mv, rm, touch, PowerShell cmdlets, nested commands, parsed by the guards' own shell parser) whose targets fall outside the write scope, the report and the temp root; the transport speaks HTTP through `http.client` with a watchdog that closes the socket at the call's total time budget and refuses response headers over 64 KB; the default guard ids are read from the guard area with `ast` (the launcher is only ever run as a subprocess, one bounded call per guard).
- Third re-check fixes: the transport watchdog now shuts the socket down before closing it and reads with `read1`, so a server that trickles its headers or its body is cut at the call's total time budget (tested against real loopback servers); `HTTPS_PROXY` and `https_proxy` are honoured through a CONNECT tunnel (an http:// proxy URL, its credentials become a Basic Proxy-Authorization header) and `NO_PROXY` and `no_proxy` match host names and domain suffixes; the task's spend is the larger of its state file and the Cost USD of its ledger row, so deleting the state file cannot reset the cap; the shell write check of the sdk policy resolves a relative target against the folder a `cd`, `pushd`, `chdir`, `Set-Location` or `sl` moved into and denies the write when that folder cannot be resolved statically.
- Shell-write check, pipe and xargs: a writer at the end of a pipe or under `xargs` writes what its input names, so it is judged against the project root: literal paths inside the write scope pass, anything else (or an input it cannot know) is denied.
