- Area `size`: `size lint` validates the sizing (C23) through the contract area, then cross-checks it against the contract catalog (every Boundaries contract and unit dependency is a row, an absent catalog is a FAIL naming the path), warns about each component without a unit (never a failure), and prints estimate totals per unit and per repository.
- Area `tech`: `tech lint` fails any Technology matrix row without an exact version, a primary source URL or an existing verified date, warns beyond a configurable age (90 days by default), and checks the C25 decisions, including the passed spike a risky chosen candidate needs.
- Area `adr`: `adr new` writes the next ADR from the template; `adr lint` checks C24, unique ids, reciprocal supersession links (a self-supersession fails), overdue `review-by` triggers (warning) and that an Accepted ADR's technology evaluations are decided.
- Area `spec`: `spec new` (tiers S, M, L), `spec lint` (C05, a runnable Gate per requirement, interfaces resolved against the catalog, requirement ids never reused across specs, plan with a constitution check and a "simpler alternative rejected" column), `spec trace` (C08 from the spec rows, tasks and `# REQ:` or `// REQ:` markers; byte-stable), `spec show`, `spec approve`, `spec hook-approval` and `spec freeze --check` (VALID or VOID).
- The freeze approval (C06) is created only from the human's typed phrase `approve <spec id> <first 12 hex of the spec sha256>`, by the `spec-approval` UserPromptSubmit handler (`HOOKS` in the spec area) or by `spec approve`; it hashes the spec, the referenced contracts and Accepted ADRs and the named tests, LF-normalized, and any later change, deletion or addition voids it.
- Shared modules `batuta_lib/spec_model.py` (comment stripping, spec reading, gate rules, named tests, catalog and ADR lookups, hashes), `approval.py` and `trace.py`; templates in `plugins/batuta/templates/spec/` (spec, plan, tasks, test change requests, constitution with tiers, ADR).
- Review fixes: `spec approve` reads the phrase from the console device and refuses piped input; `spec hook-approval` is a dry run; Gate cells must be runnable and name something the freeze hashes (paths normalized, escapes refused); approval records are ordered by instant and a future-dated record is ignored; ADR supersession cycles and a superseded ADR still Accepted fail; `spec new` no longer writes `test-change-requests.md`; `tech lint` reports a malformed table as a FAIL item and a future verified date as a warning; the REQ marker reader uses `tokenize` for Python and a string-aware scanner for JavaScript.
- Re-check fixes: the console probe (a Windows console handle, a POSIX tty and `/dev/tty`) with a 300 second timeout; a Gate must yield a hashable test file; chains that can never fail and prose spans are refused; the JavaScript marker reader tracks regex literals; echoed pieces of the typed prompt are clipped under the C16 limit.
