- Area `device`: `device deploy` copies the plugin's scripts, contracts, templates and on-demand reference files into a device copy (`--deploy-root`, else `BATUTA_HOME`, else `~/.batuta`) and writes its profile (C15); `device restore` merges the settings presets append-only into `~/.claude/settings.json` (backup first, then re-read and re-merge what a running session dropped, 3 attempts), renders the user core from its configured template and installs path-scoped rule stubs with links rewritten to resolve from the installed location; `device check` (and `--hook`, the `session-check` handler) reports OK or INCOMPLETE with the exact fix in under two seconds; `device backup` collects the learned state into a bundle folder and refuses on any secret pattern.
- Area `preflight`: `preflight limits` prints CPU count, memory, free disk per root, GPU (optional), Python and Node; `preflight prereqs --register FILE` runs each owner-prerequisite probe with a timeout and reports present or missing with the owner action.
- Shared modules `batuta_lib/device_profile.py` (device roots resolved from configuration and environment, validated after `$VAR` expansion) and `batuta_lib/settings_merge.py` (append-only presets merge verified after the write).
- Templates: `templates/presets/base.json` (subagent model, spawn depth and concurrency caps from the configuration, deny and ask rules) and `templates/presets/session-check.json` (the SessionStart entry, rendered per device), and `templates/managed-settings.example.json` (the organization layer users cannot remove).
