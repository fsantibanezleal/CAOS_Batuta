- Hook launcher `plugins/batuta/scripts/hook.py <handler id>` (contract C31): finds the handler by reading the area modules' literal `HOOKS` dict with `ast`, imports only the defining module, validates the handler result, prints the C16 output (at most 10,000 characters), writes the message of an exit-code-2 result to stderr, and exits 1 with the reason on an unknown or duplicated id, an import failure, an exception, an invalid result or an oversize output (a non-blocking error: the launcher fails open; `onFailure: "block"` in hooks.json makes an entry fail closed). Writes no bytecode.
- Area `guard`: six PreToolUse handlers (`guard-automation`, `guard-locked-tests`, `guard-approvals`, `guard-secrets`, `guard-destructive`, `guard-require-brief`), each with positive and negative pattern tests. The automation rule table matches after NFKC and lookalike folding, with PowerShell backtick, caret and quote obfuscation removed, inside nested commands and decoded `-EncodedCommand` payloads. The locked-test guard reads the C07 lock file (`tdd.lock_file`, default `.batuta/test-locks.json`) and covers Edit and Write plus shell writes (redirects, tee, sed -i, cp, mv, rm, git checkout, PowerShell cmdlets, inline interpreters), and points to the C33 change-request row to add.
- `batuta.py guard <name> --payload FILE [--explain]` runs one guard; `batuta.py guard scan --diff RANGE [--root DIR] [--ignore GLOB]` is the CI twin that runs the automation and destructive packs over the added lines of a diff.
- Area `leaks`: `batuta.py leaks scan [--root DIR] [--deny-list FILE] [--allow-email PATTERN]` scans tracked and untracked-not-ignored files for user paths, e-mail addresses outside an allow-list, GitHub, Anthropic, OpenAI, AWS, Slack and Google tokens and private keys, and the terms of a private deny-list file that must live outside the repository (a path inside it is refused; terms and secrets are never printed).
- `docs/reference/enforcement-matrix.md`: every rule, its handler id, its script or CI equivalent, whether its hooks.json entry needs `onFailure: "block"`, the configuration keys the guards read, and the known limits.
