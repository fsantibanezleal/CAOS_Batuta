## [0.01.000] - 2026-10-29

The first release: the data contracts C01 to C34, the command areas, the hook launcher and its guards, the agents and
skills, the plugin marketplace, the npx entry and the copier-compatible project template, the documentation wiki and the
end-to-end self-test, with CI green on Linux and Windows for Python 3.10 and 3.13.

The output budget of a call is bounded by what the cap still buys, a projected cost over the cap stops the run before anything is sent, and an answer that costs more than the cap is discarded and recorded as `over-budget` with its partial cost.

- `tdd commit --red|--green|--refactor T-NNN -m TITLE PATH... [--approved ID] [--body TEXT] [--apply]` stages explicit files and writes a C32 message; it refuses a red with a non-test file or an unlocked test, a green or refactor that touches a locked test or the lock file, a green without an earlier red for the task, anything else already staged and a subject over 72 characters.
- `tdd check [--range R] [--replay] [--config PATH]` proves from git history that every green follows a red of its task, that a red holds locked failing tests and the lock only, that no commit touches a path locked at its parent, that the lock is append-only (a green or refactor adds no entry but superseding ones) and every superseding entry names an approved request, that every locked file still matches its newest entry at the end of the range, that no commit adds a skip, expected-failure, only, todo or focus marker (aliases and imports resolved; `conftest.py`, test `__init__.py` and runner settings read too) and that a test file's assertions never drop; a merge is checked against every parent; settings come from the range's base commit and a change of them inside the range is a `WARN`; the only exemption is a `Test-Change-Approved: <id>` trailer naming a request approved in an earlier commit, for that path, whose spec changed in the same range.
- `--replay` checks each red commit out in a temporary worktree under the configured temp root and runs the project's own test command once (the configured `tdd.test_command`, else unittest discovery from the checkout root, `-t .` when `tests` is a package); a red counts only when a test of its own fails or errors (exit 0, exit 5 and `Ran 0 tests` do not count); the worktree is removed even when the test command fails or times out.

- `gate thresholds`: the C11 ratchet. `--check` replays the history (chain, dates, same-date human waivers of L9-promote for every decrease, values equal to the history's end) and, with `--against REF`, the committed baseline (append-only history, nothing removed or lowered silently); `--propose name=value` records a raise in the history and refuses a decrease without a waiver and a reason.
- `gate promote`: the port of the merge gate. The merge command is printed and run only with `--apply`.
